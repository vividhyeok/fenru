# 병합 및 동기화

현재 동작하는 경로는 ZIP 내보내기/병합 복원입니다. Drive 네트워크 동기화는 구현되지 않았습니다.

로컬 저장 시 기기별 벡터 카운터를 증가시키고 outbox에 객체 ID와 revision을 원자적으로 기록합니다. 수신 벡터가 로컬을 지배하면 수신 객체를 적용합니다. 로컬이 지배하면 로컬을 유지합니다. 양방향 변경은 동시 변경으로 판단하여 로컬을 유지하고 결정적 SHA256 ID의 충돌 복사본을 생성합니다. 동일 백업 재적용은 같은 충돌 복사본을 중복 생성하지 않습니다. 동시 삭제/수정은 삭제 내용까지 보존하고 검토 가능한 복사본으로 남깁니다.

ZIP 검증은 manifest 스키마, 경로, symlink, 해제 총량과 모든 파일 체크섬을 확인한 후 DB 트랜잭션을 시작합니다. 파일은 임시 경로에 기록한 뒤 rename합니다. 트랜잭션 실패 시 참조되지 않는 파일이 남을 수 있으나 기존 객체를 삭제하지 않습니다.

이후 Drive 구현은 immutable 객체별 연산 업로드 → checksum 확인 → 원격 cursor 저장 → ACK된 revision만 outbox 제거 순서가 필요합니다. 토큰은 동기화에서 제외하며 SQLite 자체/FTS 인덱스는 업로드하지 않습니다. OAuth·재시도·백오프·resume·용량 부족·두 실제 기기 검증 전에는 동기화 완료로 표시하면 안 됩니다.
